[지도·API 오류와 개선 Q&A]

Q1. 카카오 지도가 보이지 않을 때 무엇을 확인해야 하나요?

A. 다음 순서로 확인합니다.

1) JavaScript API 키가 설정됐는지
2) 키 형식이 올바른지
3) 카카오 콘솔에 현재 도메인이 등록됐는지
4) 지도 SDK 요청이 네트워크에서 성공했는지
5) map-api 요소에 높이가 설정됐는지
6) 브라우저 콘솔에 JavaScript 오류가 있는지


Q2. 지도 div의 높이가 왜 필요한가요?

A. 지도 객체가 정상 생성되어도 컨테이너 높이가 0이면 화면에 보이지
않습니다. CSS에서 지도 영역의 width와 height를 확인해야 합니다.


Q3. GeoJSON 경계가 표시되지 않으면 무엇을 확인해야 하나요?

A. 파일 경로, HTTP 상태, JSON 파싱 오류, geometry.type,
좌표의 경도·위도 순서를 확인합니다. 로컬 파일을 직접 열기보다
로컬 웹 서버를 통해 실행해야 fetch 제한을 피할 수 있습니다.


Q4. 마커가 엉뚱한 위치에 표시되는 원인은 무엇인가요?

A. 위도와 경도 순서를 바꿨거나 CSV 좌표가 잘못됐을 가능성이 큽니다.
카카오 LatLng는 `(위도, 경도)` 순서입니다.


Q5. 마커가 중복되는 원인은 무엇인가요?

A. 새 마커를 만들기 전에 이전 마커에 `setMap(null)`을 호출하지 않았거나
기존 마커 배열을 비우지 않았을 수 있습니다.


Q6. 같은 위치의 음식점이 하나만 보이는 이유는 무엇인가요?

A. 같은 좌표의 음식점을 마커 하나로 묶었기 때문입니다.
정보창의 이전·다음 기능으로 같은 위치의 다른 음식점을 확인합니다.


Q7. 필터를 바꿨는데 마커가 그대로인 이유는 무엇인가요?

A. 선택 상태를 바꾼 뒤 `updateMarkerVisibility()`가 호출되는지,
음식점의 district와 category 값이 필터 값과 정확히 일치하는지 확인합니다.


Q8. 즐겨찾기 목록과 지도 마커가 일치하지 않는 원인은 무엇인가요?

A. 두 데이터의 식별 키 형식이 다르거나 음식점 이름과 행정동이 서로
일치하지 않을 수 있습니다. 현재는 `행정동|음식점명` 키로 연결합니다.


Q9. 이름으로 즐겨찾기를 연결하는 방식의 한계는 무엇인가요?

A. 같은 행정동에 동명 음식점이 있거나 이름이 수정되면 잘못 연결될 수
있습니다. 장기적으로는 음식점마다 변하지 않는 고유 ID를 사용하는 것이 좋습니다.


Q10. 현재 위치가 동작하지 않는 원인은 무엇인가요?

A. 위치 권한 거부, HTTPS가 아닌 환경, 기기 위치 서비스 비활성화,
시간 초과 또는 브라우저 미지원 가능성이 있습니다.


Q11. localhost에서는 GPS가 동작하나요?

A. 일반적으로 localhost는 개발 편의를 위해 보안 컨텍스트로 인정됩니다.
실제 배포 사이트에서는 HTTPS를 사용해야 합니다.


Q12. 주변 맛집 거리가 실제 내비게이션 거리와 다른 이유는 무엇인가요?

A. 주변 맛집은 하버사인 공식의 직선거리이고,
내비게이션 경로는 실제 도로망을 따라 계산한 거리이기 때문입니다.


Q13. 길찾기 API에서 401 오류가 발생하면 무엇을 확인해야 하나요?

A. REST API 키가 정확한지와 Authorization 헤더가
`KakaoAK 키값` 형식인지 확인합니다.


Q14. 403 오류가 발생하면 무엇을 확인해야 하나요?

A. 카카오모빌리티 API 사용 설정, 애플리케이션 권한,
서비스 이용 조건 또는 접근 제한을 확인합니다.


Q15. HTTP는 성공했는데 경로가 없는 경우가 있나요?

A. 있습니다. 서버 요청은 성공했지만 출발지와 도착지 사이에 자동차
경로가 없을 수 있습니다. 그래서 `result_code`도 별도로 검사합니다.


Q16. 새 경로를 검색했는데 이전 선이 남는 이유는 무엇인가요?

A. 새 Polyline 생성 전에 이전 `routePolyline`에
`setMap(null)`을 호출하지 않았기 때문입니다.


Q17. API 요청을 연속으로 보내는 문제는 어떻게 막나요?

A. 요청 중에는 길찾기 버튼의 `disabled`를 true로 설정하고,
finally에서 다시 false로 바꿉니다.


Q18. API 키를 GitHub에 올렸다면 어떻게 해야 하나요?

A. 단순히 파일에서 지우는 것만으로는 부족할 수 있습니다.
해당 키를 폐기 또는 재발급하고, 새 키에 도메인과 API 제한을 적용해야 합니다.


Q19. REST API 키를 더 안전하게 관리하려면 어떻게 해야 하나요?

A. 프런트엔드가 카카오 서버를 직접 호출하지 않고 자체 백엔드에 요청합니다.
백엔드가 환경 변수의 REST 키로 카카오 API를 호출한 뒤 필요한 결과만
프런트엔드에 전달하는 구조가 좋습니다.


Q20. 현재 지도 코드에서 개선할 수 있는 점은 무엇인가요?

A. 다음과 같은 개선이 가능합니다.

- 음식점 이름 대신 고유 ID 사용
- REST API 호출을 백엔드로 이동
- 카카오와 Google 지도 사용을 한 서비스로 통일
- 마커 수가 많을 때 클러스터링 적용
- API 요청 취소와 중복 요청 방지 강화
- 오류 메시지와 재시도 버튼 개선
- 자동화된 지도 기능 테스트 추가


Q21. 마커를 모두 다시 만드는 방식의 단점은 무엇인가요?

A. 데이터가 매우 많으면 생성과 이벤트 등록 비용이 커질 수 있습니다.
현재 규모에서는 단순하고 안전하지만, 규모가 커지면 기존 마커 재사용,
클러스터링 또는 화면 범위 기반 로딩을 고려할 수 있습니다.


Q22. 발표에서 이 지도 기능의 핵심을 한 문장으로 설명한다면?

A. 춘천 음식점 CSV와 행정구역 GeoJSON을 지도에 결합하고,
지역·카테고리·즐겨찾기 필터, GPS 주변 검색과 자동차 길찾기까지
연동한 음식점 탐색 기능이라고 설명할 수 있습니다.
